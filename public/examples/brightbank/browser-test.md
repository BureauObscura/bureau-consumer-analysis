## Storefront mockup workflow

- Complete PDP visually displayed the creative, $28.80 price, $6.95 shipping, sugar disclosure, ingredients, nutrition, storage, returns and support information.
- Add-to-cart opened the matching cart with one 12-pack.
- Entering BRIGHT10 showed an accepted-code message and carried the code into the checkout URL.
- Empty required contact fields prevented progression.
- Contact and shortened address steps accepted fictional test entries and advanced in order.
- The shipping step displayed discounted merchandise $25.92, shipping $6.95, tax $2.30 and total $35.17. The undiscounted path displayed $28.80 + $6.95 + $2.50 = $38.25.
- Express wallet selection disabled the card fields and displayed a simulated-payment notice.
- Review submission displayed **Simulated order complete** and confirmed that no payment was collected or data saved.
- The product-facts PDF was rendered and visually checked as a legible single page.

The mockup's five-step guest/wallet path was exercised. PayPal was verified as an available option but not completed as a separate path. Baseline card requirements and remaining scenario forms were covered by source generation and API HTML extraction, not eight separate manual checkout sessions. Mock form timing/error probabilities are input assumptions, not measured behavior of these forms.

## Automated checks

- TypeScript, ESLint, all 14 engine regression tests and the production build passed.
- The local HTTP integration suite passed authentication, origin, ownership, source-byte preservation, malformed-upload rejection, inert HTML, private-URL rejection, canonical evidence, analysis provenance, concurrent duplicate saves and missing-key rejection.
- The example script uploaded 27 actual assets, saved and reopened the study, evaluated eight journeys across 10M IDs, saved/read the frozen result, evaluated six prices across 10M IDs, and ran three explicitly labeled 200k-ID sensitivity cases.
- It checked funnel/segment/loss reconciliation, paired counts, zero purchases from structurally excluded profiles, checkout-stage isolation, deterministic partition replay and 57 individual outcome/economics records.

Source-presentation corrections after the first browser run aligned field counts, address fields, coupon carry-through and charge timing with the declared assumptions. The final assets were uploaded and the complete automated study rerun. Numerical outcomes remained identical to the browser run.

## Not established

Paid GPT creative/PDF interpretation, positive live URL import through Jina, real ad-platform delivery, real payment providers, mobile-device interaction, a complete accessibility audit and predictive validity against customer purchases were not tested. No provider key or real campaign was used. HTML uploads preserve text/form evidence; they do not run the submitted site inside ten million browsers.
